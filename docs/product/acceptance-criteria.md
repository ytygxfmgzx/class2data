## 1. 使用方式

本文用于开发、测试和验收。开发切片完成后，至少应满足对应切片的验收标准；如果某项标准因为工程尚未初始化、平台能力缺失或范围调整无法验证，必须在交付说明中明确记录。

验收标准分为三类：

| 类型 | 含义 |
| --- | --- |
| 功能验收 | 用户能完成对应任务，数据状态正确。 |
| 业务规则验收 | 课包、流水、附件、备份等核心规则不被破坏。 |
| 状态验收 | 空状态、错误状态、边界状态可理解、可恢复。 |

## 2. 全局验收标准

### G1. 平台范围

- 第一版默认发布支持 Android、鸿蒙、iOS。
- 用户核心路径不依赖云服务、Web 后台或多用户协作。
- 同一套产品规则在 Android、鸿蒙、iOS 上保持一致。

### G2. 本地优先

- 数据库和附件默认保存在 App 私有目录。
- App 不默认把照片、付款截图、奖状或合同截图写入系统相册。
- 用户可以通过备份或导出主动带走数据。
- App 离线时仍可完成建档、记录上课、查看余额、查看历史和导出备份。

### G3. 数值精度

- 金额不得使用浮点数存储，应使用整数分单位。
- 课时不得使用浮点数存储，应使用定点整数，例如 `100 = 1 课时`。
- 展示层可以显示 `0.5`、`1`、`1.5` 等用户可读格式。
- 上课次数、实际上课时长、消耗课时、费用投入必须分开计算。

### G4. 类型和标签

- 系统语义类型使用稳定 code，不允许用户改名或新增业务含义。
- 普通分类标签允许新增和隐藏。
- 历史记录必须保存当时的普通标签显示名称快照。
- 标签改名或隐藏不得改变历史记录含义。

### G5. 删除和归档

- 有历史记录的孩子、课程和课包不得无提示硬删除。
- 影响账本的作废、调整或删除操作必须可解释。
- 新建后未产生关联数据的草稿对象可以硬删除。
- 删除附件记录时，必须直接删除对应的私有目录文件。

## 3. Slice 1 基础壳和本地数据库

### AC-S1-01 App 启动

- Given 用户首次安装 App
- When 用户打开 App
- Then App 能进入首页
- And 首页能展示适合空数据的入口

### AC-S1-02 基础路由

- Given App 已启动
- When 用户切换底部导航
- Then 可以进入首页、课程、回顾、设置四个主区域
- And 返回路径不丢失当前主区域语义

### AC-S1-03 数据库初始化

- Given App 首次启动
- When 本地数据库初始化完成
- Then 系统语义类型和普通标签预置数据可读取
- And 初始化失败时应显示可理解的错误状态

### AC-S1-04 质量门禁

- Given Flutter 工程已初始化
- When 执行基础质量检查
- Then `dart format .`、`flutter analyze`、`flutter test` 应通过

## 4. Slice 2 孩子与课程建档

### AC-S2-01 添加孩子

- Given 当前没有孩子数据
- When 用户填写孩子名称并保存
- Then 系统创建孩子
- And 首页或课程区不再展示“没有孩子”的空状态

### AC-S2-02 孩子表单校验

- Given 用户正在添加或编辑孩子
- When 孩子名称为空
- Then 系统阻止保存
- And 提示名称必填

### AC-S2-03 添加课程

- Given 已存在一个孩子
- When 用户为该孩子添加课程并填写课程名称
- Then 系统创建归属于该孩子的课程
- And 用户可以从孩子详情或课程列表进入课程详情

### AC-S2-04 课程默认值

- Given 用户正在创建课程
- When 用户填写默认扣课时和默认时长
- Then 系统保存为该课程后续记录上课的默认值
- And 默认值变更不影响已经保存的历史上课记录

### AC-S2-05 课程表单校验

- Given 用户正在添加或编辑课程
- When 课程名称为空、默认扣课时为负数或默认时长为负数
- Then 系统阻止保存
- And 提示对应字段需要修正

### AC-S2-06 联系人

- Given 已存在一门课程
- When 用户添加联系人并填写姓名
- Then 联系人归属于该课程
- And 联系人角色按普通分类标签处理

### AC-S2-07 归档规则

- Given 孩子或课程存在关联课包、计划、上课记录、费用、成就或附件
- When 用户尝试删除
- Then 系统不得无提示硬删除
- And 应提供归档或取消操作

## 5. Slice 3 上课计划与首页待处理课程

### AC-S3-01 创建每周重复计划

- Given 已存在一门课程
- When 用户创建每周重复计划并填写星期、开始时间和结束时间
- Then 系统保存计划
- And 首页能生成符合本周日期范围的待处理课程

### AC-S3-02 创建每天重复计划

- Given 已存在一门课程
- When 用户创建每天重复计划并填写日期范围和时间
- Then 系统在日期范围内生成近期待处理课程

### AC-S3-03 创建单次计划

- Given 已存在一门课程
- When 用户创建单次计划并填写日期和时间
- Then 首页仅在对应日期生成该待处理课程

### AC-S3-04 创建指定日期列表计划

- Given 已存在一门课程
- When 用户创建指定日期列表计划并添加多个日期
- Then 首页按日期列表生成近期待处理课程

### AC-S3-05 计划校验

- Given 用户正在创建或编辑计划
- When 结束时间早于开始时间、结束日期早于开始日期、每周重复未选择星期、指定日期列表为空
- Then 系统阻止保存
- And 提示对应字段需要修正

### AC-S3-06 暂停和结束计划

- Given 一条计划状态为暂停或结束
- When 首页生成待处理课程
- Then 该计划不应出现在待处理列表

### AC-S3-07 防重复处理

- Given 某节计划课已经生成上课记录
- When 首页再次生成同一计划课
- Then 该计划课不得重复显示为待处理
- And 应显示已处理状态

### AC-S3-08 寒暑假计划冲突提示

- Given 同一孩子已有启用计划
- When 用户录入寒暑假班或阶段性计划并与已有计划时间重叠
- Then 系统显示冲突课程、日期和时间
- And 用户可以选择修改、取消或继续保存

## 6. Slice 4 课包、续费和费用

### AC-S4-01 新建课包

- Given 已存在一门课程
- When 用户记录一次购课或续费
- Then 系统创建一个新课包
- And 不追加到旧课包

### AC-S4-02 费用记录

- Given 用户记录一次购课或续费并填写金额
- When 用户保存
- Then 系统创建关联当前课程和课包的费用记录
- And 金额以整数分单位存储

### AC-S4-03 正向课时流水

- Given 用户创建有固定总课时的课包
- When 用户保存课包
- Then 系统创建正向课时流水
- And 课包余额可由该课包关联流水求和得到

### AC-S4-04 周期卡

- Given 用户创建周期卡或不限次卡
- When 总课时为空
- Then 系统允许保存
- And 展示时不得伪造课时余额

### AC-S4-05 赠课或金额未知

- Given 用户创建赠课包或金额未知课包
- When 金额为空
- Then 系统允许保存

### AC-S4-06 付款截图

- Given 用户创建课包或费用记录
- When 用户添加付款截图
- Then 文件复制到 App 私有目录
- And 附件关联到费用或课包

### AC-S4-07 作废课包

- Given 课包已有费用或课时流水
- When 用户作废课包
- Then 历史流水不得被静默删除
- And 作废操作必须保留可解释信息

## 7. Slice 5 记录上课、请假、取消和销课

### AC-S5-01 首页快速记录

- Given 首页存在一节今天待处理课程且已有可推荐课包
- When 用户点击课程、选择已上课并保存
- Then 系统创建上课记录
- And 首页显示该计划课已处理

### AC-S5-02 10 秒路径

- Given 用户已有课程、计划和可推荐课包
- When 用户按“打开 App -> 点击课程 -> 选择状态 -> 保存”完成常见记录
- Then 产品设计应支持该路径目标不超过 10 秒
- And 添加图片、修改课时、切换课包或填写备注不计入基础 10 秒路径

### AC-S5-03 默认值带出

- Given 用户记录上课
- When 存在最近同课程同上课类型记录
- Then 系统优先带出该记录的课时、时长和课包默认值

### AC-S5-04 默认值退级

- Given 不存在同课程同上课类型记录
- When 用户记录上课
- Then 系统依次尝试最近同课程记录、课程默认值、用户手动输入

### AC-S5-05 默认值不改历史

- Given 用户修改课程默认扣课时或默认时长
- When 用户查看历史上课记录
- Then 历史记录中的课时和时长不随默认值变化

### AC-S5-06 扣课流水

- Given 用户保存一条扣课时大于 0 的上课记录
- When 系统入账
- Then 系统创建负向课时流水
- And 该流水关联当前课程、课包和上课记录

### AC-S5-07 不扣课记录

- Given 用户保存请假或取消记录且扣课时为 0
- When 系统保存
- Then 只创建上课记录
- And 不创建消耗流水

### AC-S5-08 课包推荐范围

- Given 用户记录扣课
- When 系统推荐课包
- Then 只从当前孩子课程下查找候选课包
- And 不推荐其他孩子或其他课程的课包

### AC-S5-09 推荐课包过滤

- Given 当前课程下存在多个课包
- When 系统推荐课包
- Then 自动排除已作废、已用完、已过期或未生效课包
- And 用户手动选择这些课包时需要明确确认

### AC-S5-10 推荐课包排序

- Given 存在多个可用候选课包
- When 系统推荐课包
- Then 优先最近一次同课程同上课类型使用过的课包
- And 其次最近一次同课程使用过的课包
- And 再按更早购买、更早到期排序

### AC-S5-11 待确认扣课

- Given 用户记录扣课但系统无法确定课包
- When 用户保存
- Then 系统可以创建待确认扣课
- And 不应强行选择错误课包

### AC-S5-12 图片附件

- Given 用户记录上课
- When 用户添加课堂图片并保存
- Then 图片复制到 App 私有目录
- And 附件关联到本次上课记录

### AC-S5-13 图片失败

- Given 用户添加课堂图片
- When 图片复制失败
- Then 上课记录不得误显示为已成功保存图片
- And 系统应提示附件保存失败

## 8. Slice 6 课时账本和调整

### AC-S6-01 课程余额

- Given 课程存在多条课时流水
- When 用户查看课程余额
- Then 课程余额等于该课程所有课时流水求和

### AC-S6-02 课包余额

- Given 课包存在多条课时流水
- When 用户查看课包余额
- Then 课包余额等于该课包关联流水求和

### AC-S6-03 待确认列表

- Given 存在待确认扣课
- When 用户进入课时账本
- Then 用户可以看到待确认列表
- And 列表展示日期、课程、上课类型、扣课时和备注

### AC-S6-04 待确认入账

- Given 用户为待确认扣课选择可用课包
- When 用户确认入账
- Then 待确认项关联明确课包
- And 课程和课包余额重新计算

### AC-S6-05 手动调整

- Given 用户需要修正余额
- When 用户创建调整流水并填写课时和备注
- Then 系统保存调整流水
- And 余额随流水求和结果变化

### AC-S6-06 调整备注

- Given 用户创建调整、退款或作废类流水
- When 备注为空
- Then 系统阻止保存

### AC-S6-07 修改已入账记录

- Given 上课记录已生成课时流水
- When 用户修改该记录的扣课时或课包
- Then 系统不得静默覆盖造成账本不可解释
- And 第一版可删除并重建该 `class_record_id` 下关联流水，或创建调整流水

## 9. Slice 7 成就、附件和照片墙

### AC-S7-01 添加成就

- Given 已存在一个孩子
- When 用户填写成就标题和日期并保存
- Then 系统创建归属于该孩子的成就记录

### AC-S7-02 成就关联课程

- Given 已存在孩子课程
- When 用户在成就中选择课程
- Then 成就关联该课程
- And 课程回顾中可以体现该成就

### AC-S7-03 成就附件

- Given 用户创建成就
- When 用户添加奖状或照片
- Then 文件复制到 App 私有目录
- And 附件关联到成就

### AC-S7-04 附件相对路径

- Given 附件保存成功
- When 系统写入数据库
- Then 数据库保存相对路径和元数据
- And 不保存依赖系统环境的绝对路径

### AC-S7-05 删除附件

- Given 附件记录存在且文件存在于 App 私有目录
- When 用户删除附件记录
- Then 系统直接删除对应文件
- And 照片墙不再展示该附件

### AC-S7-06 丢失文件

- Given 附件记录存在但文件本体丢失
- When 用户打开照片墙或附件列表
- Then 系统不得展示为正常图片
- And 应显示文件异常状态

### AC-S7-07 照片墙筛选

- Given 存在多张照片附件
- When 用户按孩子、课程或月份筛选
- Then 照片墙只展示符合筛选条件的照片

## 10. Slice 8 统计与成长时间线

### AC-S8-01 课程统计

- Given 课程存在上课记录、费用记录和课时流水
- When 用户查看课程统计
- Then 系统展示上课次数、实际时长、消耗课时、费用投入、当前剩余、成就数量和照片数量

### AC-S8-02 统计口径

- Given 一次集训记录时长 180 分钟且消耗 2 课时
- When 用户查看统计
- Then 上课次数增加 1
- And 实际时长增加 180 分钟
- And 消耗课时增加 2

### AC-S8-03 周期卡展示

- Given 课程存在无固定总课时的周期卡
- When 用户查看余额或统计
- Then 系统展示周期卡、有效期或不限次语义
- And 不伪造课时余额

### AC-S8-04 孩子时间线

- Given 孩子存在购课、上课、成就和照片
- When 用户查看孩子时间线
- Then 时间线按日期聚合展示这些事件

### AC-S8-05 空状态

- Given 当前没有统计数据、成就或照片
- When 用户进入回顾页
- Then 系统展示清晰空状态
- And 提供添加记录或返回相关页面的入口

## 11. Slice 9 备份、恢复和导出

### AC-S9-01 导出完整备份

- Given App 中存在数据库数据和附件
- When 用户导出完整备份
- Then 系统生成普通 zip 备份包
- And 备份包包含 manifest、数据库或结构化数据、附件目录

### AC-S9-02 manifest

- Given 用户导出完整备份
- When 系统生成 manifest
- Then manifest 记录应用版本、数据库版本、导出时间和附件清单

### AC-S9-03 普通导出

- Given 用户导出备份包
- When 第一版生成备份
- Then 不要求密码加密
- And 不应阻塞用户完成普通导出

### AC-S9-04 恢复确认

- Given 用户选择备份包恢复
- When 系统校验备份包通过
- Then 系统必须展示恢复确认
- And 用户确认后才执行恢复

### AC-S9-05 防半恢复

- Given 备份包缺文件、manifest 不匹配或版本不兼容
- When 用户尝试恢复
- Then 系统提示失败原因
- And 不得让数据库和附件进入半恢复状态

### AC-S9-06 新安装恢复

- Given 用户新安装 App
- When 用户从有效备份包恢复
- Then 主要数据和附件都可恢复
- And 课程、课包、上课记录、成就和照片可查看

### AC-S9-07 JSON / CSV 导出

- Given 用户选择导出 JSON / CSV
- When 用户选择导出范围并确认
- Then 系统生成可人工查看或长期迁移的文件

## 12. Slice 10 本地通知和打磨

### AC-S10-01 通知进入第一版

- Given 第一版首个可用版本
- When 验收功能范围
- Then 本地通知能力必须包含在第一版范围内

### AC-S10-02 通知开关

- Given 用户进入通知设置
- When 用户关闭某类提醒
- Then 系统不再发送该类本地通知

### AC-S10-03 本周课程提醒

- Given 用户开启本周课程提醒且存在本周计划课
- When 到达提醒时间
- Then 系统发送本地通知
- And 通知内容来自本地计划数据

### AC-S10-04 课时不足提醒

- Given 用户开启课时不足提醒且课程余额低于阈值
- When 系统检查本地余额
- Then 系统发送本地通知

### AC-S10-05 课包快过期提醒

- Given 用户开启课包快过期提醒且存在快到期课包
- When 系统检查本地课包
- Then 系统发送本地通知

### AC-S10-06 通知权限

- Given 用户拒绝系统通知权限
- When 用户进入通知设置
- Then App 显示权限状态
- And 提供重新开启系统权限的指引入口

### AC-S10-07 不依赖云服务

- Given 设备离线
- When 本地通知触发条件满足
- Then 通知能力不依赖云端服务

## 13. 范围外验收

### AC-OOS-01 不做云同步

- 第一版不得要求用户登录云账号才能使用核心功能。
- 第一版不得依赖云同步完成余额、记录、附件或备份恢复。

### AC-OOS-02 不做多用户协作

- 第一版不提供多家长实时协作、权限分配或冲突合并。

### AC-OOS-03 不做 Web 后台

- 第一版不要求提供 Web 管理后台。

### AC-OOS-04 不做完整自动排课

- 第一版只验收寒暑假班计划录入和冲突提示。
- 第一版不验收自动生成多套排课方案。

### AC-OOS-05 不做备份加密

- 第一版备份包使用普通导出。
- 第一版不验收密码加密备份包。
