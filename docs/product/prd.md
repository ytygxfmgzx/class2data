## 1. 背景

家庭中可能有多个孩子，每个孩子同时参加多门课外兴趣班。不同培训机构的课时、费用、请假、补课、寒暑假班、集训和周期卡规则不同，数据分散在机构小程序、老师表格、微信群通知和家长自己的记忆里。

本产品不是培训机构管理系统，而是家长手机端自用的课外班记录工具。第一版重点解决日常记录、课时对账、费用回顾、成长记录和本地数据可控问题。

## 2. 产品定位

一句话定位：

> 手机优先、本地数据优先的家庭课外班账本和成长档案。

第一版产品需要让家长做到：

- 快速记录今天上了什么课、是否销课、是否请假、是否补课。
- 清楚知道每门课还剩多少课时、花了多少钱、上了多少次、上了多长时间。
- 能处理课时包、周期卡、寒暑假班、集训课、赠课包等不同权益形态。
- 能保存付款截图、课堂照片、奖状和其他附件。
- 能完整备份、恢复和导出自己的数据。

## 3. 目标用户

### 3.1 主要用户

有 1 个或多个孩子、需要自行管理课外班记录的家长。

典型特征：

- 孩子同时参加多门兴趣班或学科类课程。
- 不同课程来自不同机构，记录口径不统一。
- 需要自己核对课时、费用和上课历史。
- 日常记录发生在手机上，时间碎片化。
- 关注数据隐私，不希望照片、付款截图和账本默认散落到系统相册或云端。

### 3.2 暂不服务的用户

- 培训机构管理员。
- 多个家长协同管理同一套数据的家庭团队。
- 需要云端同步、多设备实时协作或 Web 后台的用户。

## 4. 核心问题

| 编号 | 问题 | 第一版解决方式 |
| --- | --- | --- |
| P1 | 课时余额散落在机构小程序、老师表格和个人记忆中，难以对账。 | 建立孩子课程、课包和课时流水，余额由流水计算。 |
| P2 | 课程购课方式不同，课时包、周期卡、寒暑假班、集训规则不一致。 | 课包支持不同系统语义类型，一次购课或续费形成一个新课包。 |
| P3 | 日常上课记录如果太麻烦，用户会放弃记录。 | 首页生成待处理课程，常见记录目标不超过 10 秒。 |
| P4 | 家长想回顾孩子在每门课上的时间、费用、成就和照片。 | 提供课程统计、孩子时间线、成就记录和照片墙。 |
| P5 | 本地照片、付款截图和账本数据需要可控、可迁移。 | 附件默认进入 App 私有目录，第一版提供备份、恢复和导出。 |
| P6 | 寒暑假自动排课诉求复杂，第一版完整算法风险高。 | 第一版记录计划和展示冲突基础信息；完整自动排课作为后续演进。 |

## 5. 产品目标和成功标准

### 5.1 第一版目标

- 让用户从空 App 开始建立孩子、课程、计划和课包。
- 让用户能从首页快速处理一节计划课。
- 让课时余额和课程投入可解释、可追溯。
- 让附件、备份和恢复从第一版就成为核心能力。

### 5.2 可衡量成功标准

- 用户能在不依赖外部表格的情况下查看课程总余额和课包余额。
- 常见路径“打开 App -> 点今天课程 -> 选择已上课 -> 保存”在目标设计上不超过 10 秒。
- 一次续费不会修改旧课包，而是创建新课包、费用记录和购入流水。
- 新安装 App 能通过备份包恢复主要数据和附件。
- 上课次数、实际时长、消耗课时、费用投入能够分别统计，不互相替代。

### 6.1 范围内

- 孩子管理。
- 孩子课程管理。
- 上课计划管理。
- 寒暑假班计划录入和冲突提示。
- 首页今天和本周待处理课程。
- 课包、续费和费用记录。
- 上课、请假、取消、缺课、补课记录。
- 课时流水、课包余额和课程总余额。
- 手动课时调整和待确认扣课。
- 成就记录。
- 照片、付款截图、奖状、合同截图等附件。
- 课程联系人。
- 课程统计、孩子成长时间线和照片墙。
- 标签管理。
- 本地备份、恢复、JSON / CSV 导出。
- 本地通知和提醒。
- 默认发布支持 Android、鸿蒙、iOS。

### 6.2 范围外

- 云同步。
- 多用户协作。
- Web 后台。
- 面向机构的班级、教师、学员管理。
- 复杂 AI 自动识别课程通知、截图或票据。
- 完整自动排课算法。
- 多设备冲突合并。
- 备份包密码加密。

## 7. 产品原则

- 手机端操作优先。
- 本地数据优先。
- 日常记录路径尽量短，目标不超过 10 秒。
- 一次购课或续费必须形成一个新的课包。
- 课时余额由课包和课时流水计算，不靠单个余额字段手工维护。
- 默认值只是减少填写，最终以本次上课记录为准。
- 上课计划不等于实际上课记录。
- 附件默认进入 App 私有目录。
- 备份和恢复属于第一版核心功能。
- 系统语义类型不能被用户随意改名或新增业务含义。
- 普通分类标签允许自定义，但历史记录必须保留当时显示名称。

## 8. 核心概念

| 概念 | 说明 |
| --- | --- |
| 孩子 | 家庭中的一个孩子，是课程、成长时间线和照片回顾的重要维度。 |
| 孩子课程 | 某个孩子正在上的某门课，是第一版最核心的聚合对象。 |
| 上课计划 | 某门课未来或规律性的安排，用于运行时生成近期待处理课程。 |
| 课包 | 一次购课、续费或赠课形成的权益。 |
| 上课记录 | 某次上课、请假、取消、缺课或补课的事实事件。 |
| 课时流水 | 课时变化账本，购课为正向流水，销课为负向流水。 |
| 费用记录 | 购课、续费、退款或其他费用投入记录。 |
| 成就记录 | 奖项、证书、演出、比赛、阶段成果等成长事件。 |
| 附件 | 照片、付款截图、奖状、合同截图等文件。 |
| 联系人 | 老师、教练、顾问、机构联系人等。 |

## 9. 用户场景

### 9.1 初次建档

用户第一次使用 App，需要添加孩子、创建课程、填写默认扣课时和默认时长，并可选填写机构、地点和联系人。

### 9.2 创建课程计划

用户为某门课添加每周重复、每天重复、单次或指定日期列表计划。系统根据启用中的计划生成今天和本周的待处理课程。

### 9.3 续费或购课

用户购买一组新课时、周期卡、寒暑假班或赠课包后，创建新课包。系统同步记录费用和购入课时流水，并允许添加付款截图。

### 9.4 快速记录上课

用户打开首页，点击今天某节待处理课程，选择已上课、请假、取消、缺课或补课。系统带出默认课时、默认时长和推荐课包，用户可选添加课堂照片，确认后保存。

### 9.5 对账和调整

用户查看某门课的课时流水、课包余额和课程总余额。发现机构扣课口径不同或历史记录有误时，可以创建调整流水，并填写备注。

### 9.6 成长回顾

用户查看某个孩子或某门课的时间线、课程统计和照片墙，回顾费用投入、上课时长、课程照片和成就。

### 9.7 备份恢复

用户手动导出完整备份包。更换手机或重新安装后，可以从备份包恢复数据库和附件。

## 10. 功能需求

### F1. 孩子管理

用户可以添加、编辑、归档孩子。

要求：

- 孩子名称必填。
- 昵称、头像、生日和备注可选。
- 有历史记录的孩子不能无提示硬删除，应优先归档。
- 孩子详情应能进入该孩子的课程列表和成长时间线。

### F2. 孩子课程管理

用户可以为孩子添加、编辑、归档课程。

要求：

- 课程必须归属于一个孩子。
- 课程名称必填。
- 课程可以记录分类、机构名称、地点、默认扣课时、默认时长和备注。
- 课程可以关联联系人。
- 有历史记录的课程不能无提示硬删除，应优先归档。

### F3. 上课计划

用户可以为一门孩子课程创建多个上课计划。

要求：

- 支持每周重复、每天重复、单次、指定日期列表。
- 支持寒暑假班等阶段性计划录入。
- 计划包含开始日期、结束日期、开始时间、结束时间、地点、上课类型和状态。
- 计划时间与同一孩子的其他计划冲突时，应给出冲突提示。
- 暂停或结束的计划不生成待处理课程。
- 计划课运行时生成近期待处理项，不提前批量写入所有未来课程。
- 处理过的计划课不能重复显示为待处理。

### F4. 首页待处理课程

首页展示今天和本周需要处理的课程。

要求：

- 按日期和开始时间排序。
- 明确展示孩子、课程、时间、地点和处理状态。
- 已处理计划课显示已上课、已请假、已取消、缺课等状态。
- 用户可以从首页直接进入记录上课流程。

### F5. 课包、续费和费用

用户可以记录一次购课、续费、赠课或周期卡。

要求：

- 一次购课或续费必须创建一个新课包。
- 不支持把续费追加到旧课包。
- 课包可以记录类型、购买日期、生效日期、到期日期、总课时、金额、状态和备注。
- 周期卡或不限次卡可以没有固定总课时。
- 购课或续费时可以同步创建费用记录和正向课时流水。
- 付款截图可作为附件关联到费用或课包。

### F6. 记录上课、请假、取消、缺课和补课

用户可以记录一节课的实际处理结果。

要求：

- 支持从首页计划课进入，也支持手动补录。
- 支持状态：已上课、请假、取消、缺课、补课。
- 记录包含日期、时间、上课类型、实际时长、消耗课时、课包、图片附件和备注。
- 记录上课时可以直接添加图片，图片作为附件关联到本次上课记录。
- 默认值来源顺序为最近同课程同类型记录、最近同课程记录、课程默认值、用户手动输入。
- 默认值只影响表单，保存后以本次记录为准。
- 消耗课时为 0 时不创建扣课流水。
- 需要扣课时，系统创建负向课时流水。

### F7. 自动推荐课包

记录扣课时，系统应减少用户选择课包的成本。

要求：

- 推荐范围只限当前孩子课程。
- 排除已作废、已用完、已过期或未生效的课包，除非用户手动确认。
- 优先推荐最近一次同课程同上课类型使用过的可用课包。
- 其次推荐最近一次同课程使用过的可用课包。
- 再按更早购买、更早到期排序。
- 无法判断时标记为待确认。
- 用户始终可以手动改成其他可用课包。

### F8. 课时账本和调整

用户可以查看并解释每门课的课时变化。

要求：

- 课程余额和课包余额由课时流水求和得到。
- 流水区分购入、消耗、调整、退款、作废、待确认等类型。
- 手动调整必须填写备注。
- 待确认扣课可以后续补选课包并入账。
- 修改已入账上课记录时，不应静默覆盖历史导致账本不可解释。

### F9. 成就记录

用户可以记录孩子获得的奖项、证书、演出、比赛和阶段成果。

要求：

- 成就必须归属于一个孩子。
- 成就可以关联某门孩子课程。
- 成就包含日期、类型、标题、说明和附件。
- 成就进入孩子成长时间线。

### F10. 附件和照片墙

用户可以给课程、课包、费用、上课记录、成就等对象添加附件。

要求：

- 附件默认复制到 App 私有目录。
- 数据库保存相对路径和元数据，不保存依赖系统环境的绝对路径。
- 附件必须有明确归属对象。
- 删除附件记录时，直接删除对应的私有目录文件。
- 照片墙支持按孩子、课程、月份、上课记录和成就筛选。
- 附件文件丢失时不能显示为正常图片，应提示异常状态。

### F11. 联系人

用户可以为课程记录老师、教练、顾问等联系人。

要求：

- 联系人归属于孩子课程。
- 联系人可记录姓名、角色、电话、微信、备注。
- 联系人角色属于普通分类标签，可自定义。

### F12. 统计和成长时间线

用户可以按课程和孩子维度回顾。

要求：

- 课程统计至少包含上课次数、实际时长、消耗课时、费用投入、当前剩余、成就数量和照片数量。
- 上课次数、实际时长和消耗课时必须分开计算。
- 周期卡和无固定课时包不能伪造课时余额，应展示按有效期或不限次的语义。
- 孩子时间线聚合购课、上课、成就和照片。

### F13. 标签管理

用户可以管理普通分类标签。

要求：

- 系统语义类型不可由用户改名或新增业务含义。
- 普通分类标签可以新增、隐藏。
- 历史记录保存当时显示名称快照。
- 标签改名或隐藏不能改变历史记录含义。

### F14. 备份、恢复和导出

用户可以完整带走和恢复数据。

要求：

- 支持手动导出完整 zip 备份包。
- 备份包第一版使用普通导出，不要求密码加密。
- 备份包包含 manifest、数据库或结构化数据、附件目录。
- manifest 记录应用版本、数据库版本、导出时间和附件清单。
- 支持从备份包恢复。
- 恢复前必须提示用户确认。
- 备份缺文件或版本不兼容时不能半恢复。
- 支持导出 JSON / CSV，用于长期迁移和人工查看。

### F15. 本地通知

用户可以开启本地提醒。

要求：

- 本地通知进入第一版首个可用版本。
- 支持本周课程提醒。
- 支持课时不足或课包快过期提醒。
- 通知可关闭。
- 通知数据来源于本地计划和余额。
- 不依赖云服务。

## 11. 状态和边界

### 11.1 空状态

- 没有孩子时，引导添加第一个孩子。
- 有孩子但没有课程时，引导添加课程。
- 有课程但没有计划时，引导添加上课计划或手动补录。
- 有课程但没有课包时，记录上课时允许保存不扣课记录，扣课时提示先添加课包或标记待确认。
- 没有照片或成就时，展示清晰入口，不制造虚假数据。

### 11.2 错误状态

- 附件复制失败时，业务记录不能误显示为已完整保存附件。
- 备份恢复失败时，必须说明失败原因，并避免数据库和附件处于半恢复状态。
- 课包推荐无法判断时，必须显示待确认，而不是强行选择。
- 输入金额、课时、时长时必须校验非法值。

### 11.3 数据边界

- 金额不使用浮点数，采用整数分单位。
- 课时不使用浮点数，采用定点整数。
- 日期和时间按本地家庭记录语境存储和展示。
- 删除或作废影响账本的数据时必须可解释。

## 12. 隐私和本地数据

- 数据库和附件默认保存在 App 私有目录。
- App 不默认把照片和截图写入系统相册。
- 第一版不依赖云账号或云服务。
- 用户需要通过备份功能主动导出数据。
- 备份包第一版不做密码加密。
- App 卸载可能导致私有目录数据被系统删除，因此备份恢复必须从第一版开始提供。

## 13. 非功能需求

- 手机端优先，关键路径适配单手操作和碎片时间。
- 核心记录路径需要尽量减少输入和跳转。
- 数据计算应可解释，尤其是课时余额、费用投入和统计口径。
- 本地数据库迁移必须保护已有数据。
- 备份恢复需要防止半恢复。
- 页面应提供清晰的加载态、空状态和错误态。
- 第一版默认发布支持 Android、鸿蒙、iOS。

## 15. 风险

- 寒暑假班第一版只做计划录入和冲突提示，完整自动生成排课方案明确放入后续版本。
- 如果备份恢复设计后置，附件私有目录策略会给用户带来数据丢失风险。
- 如果课包余额使用单字段手工维护，后续对账和修正会变得不可解释。
- 如果日常记录路径太长，用户会回到纸笔、微信收藏或表格。
- 如果系统语义类型允许自由改名或新增，会破坏统计和业务计算。

## 16. 已确认决策

以下决策来自 2026-05-08 用户确认，作为第一版规格约束：

- 第一版默认发布支持 Android、鸿蒙、iOS。
- 备份包第一版使用普通导出，不需要密码加密。
- 本地通知进入第一版首个可用版本。
- 寒暑假班第一版只做计划录入和冲突提示，完整自动生成排课方案放入后续版本。
- 删除附件记录时，直接删除对应的私有目录文件。
- 记录上课时可以添加图片，图片作为附件关联到本次上课记录。
