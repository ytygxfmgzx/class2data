# 质量规范与验收

本文定义第一版持续开发的质量门禁。每个 agent 交付时都要说明执行了哪些验证，哪些没有执行以及原因。

## 基础命令

Flutter 工程存在后，常用验证命令：

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs
dart format .
flutter analyze
flutter test
```

如果只修改文档，不需要运行 Flutter 测试，但要检查链接、标题和术语一致性。

## 代码质量

- 禁止用 `any`、`dynamic` 或忽略规则绕过类型问题。
- 禁止保留注释掉的废弃代码。
- 业务规则必须可测试，不应藏在页面点击回调里。
- 数据库写入失败要向上返回明确错误，不吞异常。
- 中文文案要短、准确、符合家长日常表达。

## 测试分层

### 领域单元测试

必须覆盖：

- 课包选择算法。
- 课时余额计算。
- 默认值带出顺序。
- 上课计划生成近期课程。
- 统计口径。

### 数据库测试

必须覆盖：

- 核心表插入和查询。
- 多表事务。
- 迁移。
- 防重复处理计划课的唯一约束。

### Widget 测试

优先覆盖：

- 添加孩子和课程表单。
- 添加计划表单。
- 购课和续费表单。
- 处理计划课弹层或页面。
- 备份恢复确认流程。

### 集成或手工验收

第一版主路径必须验收：

```text
添加孩子 -> 添加课程 -> 添加计划 -> 添加课包 -> 首页处理上课 -> 查看余额和统计 -> 添加附件 -> 导出备份 -> 恢复备份
```

## 业务验收清单

### 孩子和课程

- 一个孩子可以有多门课程。
- 课程可以归档。
- 课程联系人挂在课程下，不单独建机构档案。

### 计划和首页

- 每周、每天、单次、指定日期列表计划能生成正确待处理课程。
- 暂停和结束计划不生成待处理课程。
- 已处理计划课显示状态，不重复待处理。

### 课包和销课

- 一次续费创建一个新课包。
- 购课创建正向课时流水。
- 上课扣课创建负向课时流水。
- 请假和取消默认不扣课。
- 余额由流水计算。
- 课包推荐不跨课程。

### 附件

- 附件默认进入 App 私有目录。
- 数据库保存相对路径和元数据。
- 备份包含附件文件。
- 文件缺失时 UI 有错误状态。

### 备份恢复

- 备份包包含 manifest、数据库和附件。
- 恢复前校验版本和文件完整性。
- 恢复失败不破坏当前可用数据。
- JSON / CSV 导出可被外部长期保存。

## 隐私与安全

- 不默认上传任何数据。
- 不默认写入系统相册。
- 不记录不必要的联系人敏感信息。
- 导出备份前提示用户备份包包含家庭隐私数据。
- 后续若增加加密，必须有恢复失败和忘记密码的说明。

## 性能门禁

第一版数据规模按家庭自用估算：

- 孩子：1 到 5 个。
- 课程：每个孩子 5 到 20 门。
- 上课记录：数千条。
- 附件：数百到数千个文件。

要求：

- 首页只生成近期计划课，不预生成长期课程。
- 照片墙分页或懒加载。
- 统计查询避免在 UI 线程做大量同步计算。

## 发布前检查

- 第一版范围内主路径全部可用。
- `flutter analyze` 无错误。
- `flutter test` 通过。
- Android 真机或模拟器完成主路径验收。
- 备份恢复在新安装环境验证。
- 文档说明运行方式、备份位置和已知限制。

## 文档验收

文档变更要满足：

- 和 `interest-class-app-design.md` 不冲突。
- 新术语第一次出现时有解释。
- 工程规则能被 agent 执行，不只是口号。
- 待确认事项明确标记，不能伪装成已定事实。
