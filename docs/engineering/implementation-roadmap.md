# 实施路线图

路线图按”可持续交付”组织。每个里程碑结束都应产生可运行、可验证的增量。

上游依据：
- [prd.md](../product/prd.md)
- [acceptance-criteria.md](../product/acceptance-criteria.md)
- [open-questions.md](../product/open-questions.md)

## 里程碑原则

- 每个阶段都要有可演示路径。
- 优先完成核心闭环，再补增强体验。
- 数据模型变更要早做，UI 细节可以逐步打磨。
- 任何阶段都不能破坏已完成的备份、余额和历史记录语义。

## 已确认产品决策摘要

以下决策影响工程实现：

| 决策 | 工程影响 |
| --- | --- |
| 首发平台：Android、鸿蒙（兼容方式）、iOS | 三平台构建和测试，鸿蒙按 Android 兼容方式运行 |
| 备份恢复：覆盖式恢复 | 恢复前确认提示，防半恢复策略 |
| 图片来源：拍照 + 相册 | 需要相机和存储权限申请 |
| 附件删除失败：保留记录，提示重试 | 删除操作需要错误处理和用户反馈 |
| 归档对象：日常列表默认隐藏 | 列表筛选需提供”查看归档”入口 |
| 手动调整：必须填写备注 | 表单校验规则 |
| JSON/CSV 导出：全量导出 | 第一版不做筛选导出 |

## M0：工程准备

目标：把空仓库变成可开发项目。

任务：

- 确认 `docs/engineering/` 文档。
- 初始化 Flutter 工程到 `app/`。
- 配置分析规则、测试目录和基础依赖。
- 建立基础 README，说明运行和验证命令。
- 明确构建目标：Android、鸿蒙（Android 兼容方式）、iOS。

完成标准：

- `app/` 可本地启动。
- 有最小测试用例。
- 新 agent 能按 `AGENTS.md` 找到工程入口。
- 三平台构建配置就绪。

## M1：基础设施与数据库

目标：建立本地优先的数据底座。

任务：

- 接入 Drift + SQLite。
- 建立核心表和初始迁移。
- 建立预置系统类型和普通标签。
- 建立 Repository 基类和错误模型。

完成标准：

- 数据库可初始化、读写和迁移。
- 核心表覆盖第一版实体。
- 预置选项可被 UI 查询。

## M2：孩子、课程和联系人

目标：完成基础档案。

任务：

- 孩子 CRUD。
- 孩子课程 CRUD。
- 联系人 CRUD。
- 课程详情页。

完成标准：

- 用户能建立“哥哥的篮球课”这类核心对象。
- 课程默认课时和默认时长可保存。
- 有 widget 或 repository 测试覆盖主要路径。

## M3：上课计划和首页

目标：首页成为日常操作入口。

任务：

- 上课计划 CRUD。
- 近期计划课生成服务。
- 首页今天和本周列表。
- 计划课处理状态识别。
- 寒暑假计划冲突提示（第一版只判断时间重叠）。

完成标准：

- 每周、每天、单次、指定日期列表都能生成近期课程。
- 已处理课程不重复待处理。
- 首页空状态能引导添加课程或计划。
- 同一孩子计划时间重叠时有冲突提示。

## M4：课包、费用和课时流水

目标：建立账本基础。

任务：

- 课包 CRUD 和作废。
- 购课/续费表单。
- 费用记录。
- 正向课时流水。
- 余额计算服务。
- 手动调整必须填写备注。

完成标准：

- 一次续费形成新课包、费用和购入流水。
- 课包余额由流水计算。
- 金额和课时没有浮点误差。
- 调整流水保存时校验备注非空。

## M5：记录上课和销课

目标：完成第一版最重要的日常闭环。

任务：

- 从首页处理计划课。
- 上课记录 CRUD。
- 默认值带出。
- 自动选择课包。
- 自动生成消耗流水。
- 待确认扣课。

完成标准：

- 常规上课记录路径不超过 10 秒。
- 请假、取消、缺课、补课各有明确行为。
- 课包选择算法有单元测试。

## M6：附件和成就

目标：支持成长档案。

任务：

- 成就记录。
- 附件文件复制到私有目录。
- 附件元数据。
- 图片选择和拍照（支持相机和相册）。
- 附件删除：记录删除时删除文件；文件删除失败时保留记录并提示重试。

完成标准：

- 成就可关联孩子和课程。
- 附件可关联上课记录、成就、课包、费用和课程。
- 文件丢失、权限失败有明确错误处理。
- 删除附件文件失败时，附件记录不被删除，用户收到重试提示。

## M7：统计、时间线和照片墙

目标：让用户能回顾投入和成长。

任务：

- 课程统计。
- 孩子时间线。
- 照片墙。
- 筛选和排序。

完成标准：

- 上课次数、时长、课时、费用分开展示。
- 时间线能聚合多类事件。
- 照片墙筛选准确。

## M8：备份、恢复和导出

目标：完成本地数据主权闭环。

任务：

- 完整 zip 备份。
- manifest 校验。
- 覆盖式恢复流程（恢复前明确提示用户）。
- JSON / CSV 全量导出。

完成标准：

- 备份包包含数据库和附件。
- 恢复前校验，失败不污染当前数据。
- 新安装环境能恢复出可用数据。
- 恢复时清空当前数据并覆盖，恢复前有确认提示。
- JSON / CSV 支持全量导出。

## M9：通知、体验打磨和发布准备

目标：达到第一版可发布质量。

任务：

- 本地课程提醒。
- 课时不足和课包过期提醒。
- 归档对象日常列表默认隐藏，提供"查看归档"入口。
- 性能、空状态、错误态和中文文案打磨。
- Android、鸿蒙（兼容方式）、iOS 打包和发布检查。

完成标准：

- 所有质量门禁通过。
- 有手工验收记录。
- 第一版范围内没有阻塞缺陷。
- 三平台构建产物可用。

## 后续版本候选

这些不进入第一版阻塞项：

- 寒暑假候选班冲突检测和排课方案。
- 数据库或备份包加密。
- App 解锁密码、指纹、Face ID。
- WebDAV / NAS / iCloud 同步。
- 微信文字或截图识别。
- 计划冲突考虑地点距离和通勤时间。
- JSON / CSV 筛选导出（按孩子、课程、时间范围）。
- 附件删除失败时保留失败状态供用户重试（当前为提示重试）。
